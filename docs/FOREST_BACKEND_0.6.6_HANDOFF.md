# 森林／雲上遺庭後端交接 — 0.6.6

2026-09-26。此輪只接合 `AREA_01_CLOUD_RUINS_EVENTS.md` §18.7，不實作 §46／§47 的整套旅程、大廳與任務清單。

## 已實作

- `forest_explorations`：每個 node 是一次探索，保存穩定 map ID `area-01-cloud-ruins`、信物、出現燈位、核心保底燈與完成時間。首次開始探索時決定；partial 續玩沿用。
- 信物沿用原本等機率選法，兩件各半；出現燈位等機率 1–5。每次探索只發一件，途中取得立即保存。重訪的取得紀錄分次保留，未新增堆疊加成或下趟攜帶規則。
- `forest_reward_rolls`：信物與核心分開記錄，支援同一盞燈同時出現兩者。核心未持有時每燈 5%，miss 同樣保存；持有後停止抽選。
- 50 分鐘完整探索計一次保底進度，達標後繼續專注不重複計次。前四次完成仍未取得核心，第五次開始保存隨機保底燈；提前抽中取消保底。
- `map_cores`：永久核心正式資料。`snapshot.mapCores` 提供 `{ mapId, itemKey, acquiredAt }`。專注與大廳使用此欄位，不再由 Archive 的展示清單推斷。
- `world_marks`：永久保存 `{ mapId, mark, seenAt }`。`recordWorldMark(sessionId, 'tree_traces_seen')` 驗證休息資格後冪等寫入；由既有動畫完成回報觸發。此回報只記錄「看過」，不決定獎勵。
- `snapshot.specialFinds` 合併新舊取得紀錄，沿用事件 ID 與 Claude 現有播放接口。沒有修改場景演出或美感。
- 新獎勵完成後直接進入 `awaiting_route`，跳過舊通關遺物二選一，避免第二套重複獎勵。保留舊存檔已在二選一階段的處理。
- 備份格式 6 包含以上四表，仍可匯入 1–5。舊星盤核心轉入正式核心表，保留首次取得時間。

## 遷移與範圍

- 舊取得物品與每盞抽選結果保留，不補抽已記錄的燈。舊 partial 若已有信物，不再補第二件；尚未取得者安排在剩餘燈位。若五盞舊抽選都已處理，不追溯補發。
- 本輪未改寫既有 25／50／90 分鐘路線或歷史進度，亦未將旧完成紀錄批次認列保底。新後端獎勵依既有 node 時長分五等份，只有 50 分鐘探索計入新版保底。
- 路線全部統一 50 分鐘、跨日旅程、五段終點、信物用途／跨趟攜帶與新版大廳屬其他任務；這些仍不可宣稱已完成。正式測試新版森林節奏請選 50 分鐘路線。
- 資料表無刪任務連動刪除：永久核心、世界記憶、探索計次與發獎紀錄不因工作任務刪除而遺失。
- 如後續接入其他地圖，呼叫端必須改為使用實際 map ID；本輪只有森林場景可玩，不能把其他地圖也計成森林保底。
