# Focus Quest 共同交接入口

建立：2026-10-02。用途：讓 Claude 桌面版與 Codex 從同一份檔案接續工作，使用者不必搬運整段 prompt。這不是新的產品企畫，也不代表下面的待辦已獲實作授權。

## 開工方式

2026-10-11 已建立共同 Git 基準與私人遠端，接續分支為 `checkpoint/progress-2026-10-11`；保存範圍、驗證及不同工作目錄接續方式見 [Git 基準交接](GIT_CHECKPOINT_2026-10-11.md)。本次不新增任何遊戲實作授權。

1. 依 `AGENTS.md` / `CLAUDE.md` 讀取專案指引，再讀本頁。
2. 找本次使用者指定的工作。沒有指定時，可整理交接和唯讀盤點；只接續已有明確授權、符合自己分工的待辦。不因表格出現項目就開發它。
3. 讀該項目的來源文件、最新回報和相關正式程式；本頁摘要不取代它們。若來源比本頁新，依來源修正狀態，不重做已完成工作。
4. 開始寫入前，確認另一個正在工作的 agent 是否寫相同檔案。沒有跨程式的即時鎖，這張表也不是鎖。共用檔案無法確認寫入者時先唯讀；不同範圍可依 `AGENT_WORKFLOW.md` 協調。
5. 結束時更新自己的交接文件，再更新本頁對應一列；交付檔案路徑、目前狀態、下一個負責人、未決問題與檢查證據。不要把工程限制變成要求使用者轉貼長 prompt。

Claude 的設計範圍包含前端外觀、動效和網頁原型；正式 App 前端、規則、移植與測試由 Codex 負責，沿用 2026-09-27 分工。若使用者之後明確改變正式前端的歸屬，再同步共同規則；本頁不自行改變歸屬。

## Claude 與 Codex 的交付格式

沿用既有交接文件，不再複製另一套完整規格。每次交付在原文件加入日期與以下資訊：

- 狀態：設計中／待使用者看預覽／待使用者試原型／可交接／實作中／待使用者驗收／完成／需釐清。
- 下一個負責人，以及可以直接接續的一個具體動作。
- 本次修改的檔案、可用素材或原型與預期行為。
- 使用者已批准的範圍與尚未定案的部分。沒有批准紀錄不得寫成已批准。
- 已執行的檢查與結果；未執行要註明，不把原型完成寫成正式 App 完成。

Claude 的工程問題由 Codex 在交接文件回覆；設計問題由 Claude 在原設計文件回覆。兩邊啟動／收到接續指令時自行讀取，使用者只需做設計選擇、試用與驗收。

## Area 03 的特殊流程

`area03/OPUS_HANDOFF.md` 仍保留 Opus → Sonnet 的歷史工作方式。目前使用者要求減少 prompt 搬運，因此可把階段指令與回報的檔案路徑作為交接入口，不要求使用者在 Claude 與 Codex 之間複製完整內容。

這不取消 Area 03 已要求的「先交修改後的靜態預覽、使用者討論定案後才實作」與「提供可試用 HTML」關卡。若仍有兩個 Claude 對話，共用檔案只解決上下文交接，不會自動喚醒另一個對話；本次未建立 Opus/Sonnet 自動派工。

## 自動化邊界

目前只有檔案交接，沒有背景監看、定時工作或跨 App 訊息橋接。檔案變更不會自行啟動 Claude 或 Codex。兩邊正在執行的舊對話也不會因規則檔更新而立刻重讀。

如之後設定 Codex 自動檢查，應先唯讀比對交接變化；只對明確已授權、已驗收且已交付的工作接續，並確認寫入範圍。無變化時保持安靜，不自動推進待使用者確認的設計，不對同一個交付反覆開工。Claude 桌面對話的自動喚醒需另行驗證可用介面，不能假定能由 Codex 直接操作。
