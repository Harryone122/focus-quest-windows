- 重跑 `lamp5-hat-test.js`，135 個位置／步伐相位组合没有 AABB 相交；這支程式實際使用各網格包圍盒，不是三角形精確碰撞。
- 6 個節點移動，最大 0.100，低於允許的 0.4。
- 外部 JSON 與 HTML 內嵌 JSON 去掉外圍空白後逐字相同。若包含 script 標籤內前後空白，不是逐位元組相同；內容沒有差異。
- 20 個互動點與全部節點皆從入口可達；兩種潮位路網相同。
- 五盞燈各在 600／1200／1800／2400／3000 秒的前一刻不亮、抵達門檻時亮，與旅人位置無關。
- ×6、×20、×60 各一次連續逐步模擬都到達 `p_bench`／`rest`，五盞燈全亮；跳到完成、重來通過。

- 本次白天滿潮五燈全亮 175 draws／72,997 triangles，夜間 169／72,693，均低於 250；反射貼圖 800×450（主畫面 1600×900）。不是硬體 FPS 測試。
- 每次載入只看到測試 harness 阻擋外部字型產生的 ERR_FAILED，沒有其他 console 錯誤。此結果不代表正式 App 已離線驗證。

## 不可直接標成通過的項目

1. **CHECKLIST 3.6／SPEC 8.3.3 落差**：中央 `c_west→c_stair` 約 0.082、`c_home→c_pillar` 0.093、`c_pillar→c_north` 0.073；北棧道 `c_north→n_lamp3` 約 0.080／0.077。另有岩面 `k_shelf→k_top` 0.075–0.147、`k_top→k_roots` 0.073。SPEC 只允許超過 0.07 的落差出現在石階或踏石跳躍；不能只因 JSON 把落差記為 steps 就算符合。應優先調整路線，或另行確認規格例外。沉階與踏石的合法落差應和這些問題分開。
2. **CHECKLIST 3.7 碰撞檢查的限制**：`measure_lib.js` 在岩面把檢查基準提高 0.10，放行部分岩面隆起；SPEC 原文是腳上 0.05 以上的岩石要算。工具通過不等於原始規格毫無例外地通過。`check.js` 也不會因落差規則不符而回傳失敗。
3. **完成休息的可見性**：預設視角下長凳旅人被亭簷遮住，已有報告與完成畫面可證。需使用者視覺測試評估，不能以到達 rest 狀態代替可見性驗收。
4. **仍須視覺／動態複核**：逐段腳底 ±3 公分、所有動作的碰撞、白鷺所有逃離／降落方向、每次漲潮只捲一次褲腳、減少動態效果與實機 FPS，尚未由本次測試完整覆蓋。

第 2 段小修的鏡框與缺板積水已有交付近照可確認；滿潮白天與夜間新截圖確認五區及倒影、五盞燈正常呈現。靜態截圖不作為閃光頻率與所有動態互動的完整證明。
