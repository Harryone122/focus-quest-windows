## A. Codex 現在可以開始

1. **設定**：「專注中的演出」安靜（預設）／現場，存檔、備份還原都要帶；切換從下一次 Focus 生效。既有存檔一律預設安靜。
2. **事件紀錄補欄位**，讓回顧與重播能重建畫面：事件 ID、地圖、探索與段數、這次專注中的有效時間（顯示到分鐘）、時段、天氣、隨機種子、當時帶著的信物、事件變體（例如雨天版）、是否跳過。已有的欄位沿用，不重複存。
3. **安靜模式的專注中表現**（§55.3）：
   - 整體調暗與降飽和度（起始值亮度 −25%、飽和度 −20%），環境音與 BGM −6 dB，專注中不播單次音效。
   - 點燈約 3 秒慢慢亮起。
   - 紀錄事件改播「小動作」版本：保留走位、姿勢與本來就慢、不亮的場景變化；拿掉 `camera.keys`、`reportCinematic`、單次音效、光柱／光環／閃光／粒子爆發、文字卡片。信物＝0.6 秒淡掉的小琥珀光點；核心＝跪下約 4 秒、2 秒淡掉的淡藍光。
   - 數值是起始值，請做成集中的常數，方便使用者試玩後調整。
4. **計時前的故事事件**（§55.5）：開場、首訪、第二次造訪在按下開始後、計時前播放完整版；有待播事件時離開演出也一起移到計時前。開始播放就給線索；可跳過；計時前的時間不算專注、不改燈的時間。
5. **回顧與重播的資料介面**：列出某次專注的燈與紀錄事件（依時間、核心另標）；依事件紀錄重建並播放一次事件，播放過程不寫任何紀錄、不改世界記憶，場景顯示事件發生前的狀態。

## 原型 v1（2026-10-14，Claude）

- 檔案：`docs/prototypes/focus-recap/index.html`（直接用瀏覽器開；`valley.bundle.js` 是 D11 影片用的正式場景打包，`audio.js` 是遊戲音檔轉成的 mp3）。原始碼在 `src/`：`page.html`（介面、時間軸、音效）＋`recap-director.js`（在正式場景作用域裡控制旅人、鏡頭、燈與洞內事件）；`build.py` 合成單檔。
- 樣本：50 分鐘專注，第 13 分鐘信物調音叉（石磬架）、第 26 分鐘線索「封住的牆」（帶著銅製風哨，風孔岩→共鳴洞）、第 38 分鐘地圖核心藏聲石。
- 流程：大廳（觀景平台長椅）淡入 → 頂部「專注結束」、底部玻璃時間軸滑入 → 鏡頭拉到全景，播放頭前進、燈跟著依序亮 → 停在事件：切到事件地點播完整版，卡片顯示「第 N 分鐘・地點」＋名稱＋一句話 → 回全景繼續 → 走到底後核心記號亮起，切進共鳴洞播完整的藍光演出 → 回長椅，右側出現「〈事項〉完成了嗎？」與「這次得到」清單。跳過／全部跳過／Esc。
- 調音叉的琥珀小演出是原型新設計（地圖裡還沒有）：調音叉掛在石磬架右柱的掛鉤上，敲石磬時共振發琥珀光與小聲波，旅人取下，腰間閃一下。藏聲石與風哨事件直接用正式場景的 `CAVE.evCore`／`CAVE.whistleCut`。
- 測試面板另有：沒有紀錄事件的樣本（25 分鐘，時間軸約 2 秒）、現場模式（只顯示時間軸，點記號重播）、筆記回想（暖色紙邊暗角＋手寫字卡）、專注中變暗預覽（亮度／飽和度滑桿）、小動作試看。

### v2 更新（2026-10-14，使用者要求）

- **時間軸可以拖**：滑過時間軸顯示「第 N 分鐘」，靠近事件記號（18px 內）會吸附並顯示事件名稱；拖曳時燈跟著播放頭亮滅、鏡頭回到全景。
  - 回顧進行中：一抓就暫停目前的事件；放在事件上 → 播那個事件，然後從那裡繼續往後播（核心仍然最後播，已經播完的核心不重播）；放在兩個事件之間 → 從那裡繼續播到下一個事件。
  - 回顧結束後（「完成了嗎？」畫面）與現場模式：放在事件上 → 只重播那一個，播完回到提問；放在空白處 → 播放頭回到終點。
  - 點一下記號等於拖到那裡放開。
- **使用者回饋：場景切換時不要卡（交給 Codex）**。原型是在每次切換時用 0.35 秒黑幕蓋住後直接換場景；在正式 App 要做到切換不掉幀。可疑點：
  1. `R.coreEnter()` 在黑幕下同步快轉約 500 次 `update()`，讓旅人走到石壇。正式版應直接把旅人與洞內鏡頭放到到達狀態，不要同步快轉。
  2. 第一次進洞、第一次播藍光等材質／shader 第一次編譯；用 `CAVE.warm()` 或預先渲染一次預熱，回顧開始前就做好。
  3. 洞內鏡頭每幀呼叫 `resizeAll()` → `renderer.setSize()`，只改投影矩陣即可。
  4. 黑幕本身可以縮短或改成交叉淡化，前提是不掉幀。

## 要注意

- 後端仍是唯一依據：事件先存檔再播放，回顧或重播失敗都不影響紀錄。
- 現場模式維持目前行為，回顧只顯示時間軸與卡片、不自動播放。
- 視窗在背景或最小化時事件照常記錄；回顧只讀紀錄。

## Codex 實作回報（2026-10-14）

### A 的接線

- 設定列「專注中的演出」已加入，舊資料預設安靜；模式保存在 session，途中改設定不改這次演出。亮度、飽和度、−6 dB、3 秒點燈及小光點時間集中在 `QUIET_FOCUS`。音量沿用既有滑桿曲線後再套 −6 dB。
- `focus_event_records` 記錄事件上下文及事件前場景；特殊發現沿用原事件 ID、session／node／run 關係，不重新抽選獎勵。地圖排程的 action 起點可在背景補算时留下紀錄，核心取得保留原點燈時間；實際演出變體與事件前世界狀態由排程回報補齊。
- 有故事的第一次 Focus 先保存 `before_focus` 佇列並保持有效時間為零。出發／離開與地圖載入後播放完整版；開始播放先存紀錄、給線索，再放行演出。跳過亦保存；重開會跳過已開始的事件。雲上開場的筆記與摸樹是同一事件的兩段，保留原走位，不會關掉 App 後自動補播後半段。
- 計時前完成時才建立計時起點與當日歸屬；沒有待播故事時沿用原出發計時。部分探索續跑不建立新的計時前故事。
- 安靜模式保留走位與姿勢，移除事件運鏡、隱藏介面、單次聲音及大光效；苗圃核心保留取鑰匙與走向鐵籠的路線。持續腳步／衣物聲保留。減少動態時不顯示小光點。
- 苗圃音場在場景交接時偶有無效數值，新增有限值保護與回歸測試，避免 Web Audio 中斷；未新增音效素材或合成聲音。

### B 可使用的介面

- `getFocusRecap(sessionId)`：這次有效秒數、模式、依時間排列的燈，以及核心取得排在最後的事件。顯示分鐘時使用 `Math.floor(effectiveSeconds / 60)`，不使用探索累積時間。
- `listReplayEvents(runId?)`：已記錄的故事／信物事件、核心取得及預留的相遇／結局類型；不列環境事件或一般信物取得。後者仍在結算回顧中。
- `getReplayEvent(recordId)`：只讀、複製出的當時場景參數。`EventPlayback` 可重新跑原場景腳本；不接世界／線索寫入回呼。`onStarted` 只給計時前流程使用，從筆記／回顧重播不得傳入寫入回呼。
- `beginBeforeFocusEvent`／`finishBeforeFocus` 是計時前專用的寫入介面，不能用於回顧重播。
- v14 備份保留設定、session 模式與待播佇列、完整事件資料；仍可匯入 v1–v13，壞的事件 JSON／模式在取代原存檔前拒絕。舊存檔缺少事件前參數的歷史事件不偽造重播。
