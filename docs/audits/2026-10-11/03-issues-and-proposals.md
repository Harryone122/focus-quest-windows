## Q01：五段後未進入最終領域

**證據：** `database.ts:1886–1895` 完整探索不檢查第五段，繼續 `insertGeneratedRoutes(depth + 1)`；`lobby/fromSnapshot.ts:63–67` 只投影 exploring／choose_route／journey_start。正式型別與原型雖有 final_ready／returned，投影未產生它們。後端尚無正式結束旅程、寫入相遇的入口。

**重現：** 記憶體 SQLite，以真實開始、50 分鐘、回顧、選下一段流程完成五次。結果 choose_route、segment=6、total=5、兩條下一段、completedJourneys=0，見 [verification.json](verification.json)。這是未完成內容，不是本次匯入的回歸。

**連帶影響：** 營火「相遇過」的世界記憶沒有正常取得流程，後續痕跡／日出無法正常推進；收藏室種莢以完成旅程數長大，正常旅程數也未增加；十件核心現在只有四圖可獲得。企畫的約 32 小時真結局估計不能用來描述當前四圖版本。

**提案：** 第五段結算原子儲存 final_ready，不生成第六段。相遇先做最小零核心／已持核心版本，儲存 encounter 記錄與回顧；返回營火後明確開始新旅程。新旅程另建 seed／nodes，不刪舊 run 歷史；普通訊物依 run 隔離，永久資料與幼苗不清空。最終劇本、玩家主動進入或回顧後接續、完成真結局後玩法，由使用者定案後實作。

**驗收：** 第五段達標不強制停止工作；結束後不能走第六段；零核心可相遇；第十核心不強播；相遇中斷可恢復；新旅程不帶普通訊物但保留核心／幼苗／線索。

## Q02：線索桌完成揭露，不等於隱藏圖可達

**證據：** `collectionRoom.ts` 有 h1／h2／h3 定義與 `hiddenPlaceProgress`；`generateRoutes` 只有四個普通 Area，沒有 pinned clues、pageFound 或 carried items 的輸入。`collection_pages` 有 schema／讀取／備份，沒有正式探索完成授予缺頁的流程。

**提案：** 從 h1 做一條完整切片。路線生成讀取已釘三線索、本趟兩信物、已取得缺頁、剩餘段數；條件滿足才新增第三張候選。它佔五段之一、不發普通訊物或核心，完成後先儲存缺頁，再播放收藏回收。首次相遇前是否可以入灣、缺頁取得後是否能重訪，仍需定案；不能把「暫定不能重訪」直接寫死。

**驗收：** 第二段末湊齊物品能進第三段；第五段完成後才湊齊不生成第六段；動畫失敗仍保留缺頁；缺頁不是十核心真結局條件。

## Q03：雲上古井漏收可永久阻斷 h1

**證據：** `cloudStoryForSession` 以 `forest_explorations` 列數計 visit；`cloudStorySchedule` 和 `cloudStoryClueTimes` 只在 visit===2 排古井 h1a／石碑刻度。小於五分鐘結束時 node 回到 selected（進度仍 0），`selectExpeditionNode` 允許改選同岔路另一候選；探索安排那一列仍存在。

**本次實際路線重現：** 第一探索完成；隨真實候選重訪 01 到 visit=2；10 秒結束，改走同岔路另一圖，完成它；之後再選 01，visit=3、h1a 缺失、well 不排入。測試沒有修改候選地圖、線索、玩家存檔或正式程式。結果記於 verification.json 的 cloudRetry。

**提案：** 首訪／二訪知識按永久線索缺失補排，單次演出按探索 ledger 防重播。若需保留「第二次才看到」，用前置知識與探索起始快照決定，不把精確數字 2 當唯一視窗。沿用已允許提前回顧取得的開場例外，不要求所有故事一律重播。

**驗收：** 10 秒改路、21 分鐘前中斷、備份匯入、第三／第四重訪，都能補到缺失 h1a；同例項已播不重播；永久線索只一份；同時補查 c01_stele_scale 與 c01_bark_date。

## Q04：營火第一段需要明確的保證例外

**證據：** `chooseRouteAreas` depth=0 固定 01／02 的條件包含「已擁有湖鏡」，且起點池排除 07。給定已擁有 01／02／03、未有 07，首輪仍只給 01／02。§52 明確說 07 不是第一段候選；§49.2 的通用文字則說每次候選至少一圖核心未有（剩餘可用圖都已有才例外）。

**判斷：** 07 不在第一段是批准的方向；不是逕自解除限制的理由。問題在「每次」保證的範圍沒寫清楚。

**提案：** 先將保證限定為當次可用候選池，寫明營火初段／未製作地圖例外。若使用者希望全旅程都有定向保證，再由設計補可用第一段與剪影，不直接把 07 放入開場。

## Q05：取得、看懂、相遇回收需要三套清楚契約

**證據：** CORE_UNDERSTANDING_CLUES 目前只有 01／02／03／07／10；01 讀 h2b（10 的事件未上線）。02 的 c08 事件有定義，但 ensureMossState 的 coreEvents 只放 story_core_newtag。05 交接明列藏聲石理解條件未定。其餘核心不能由收藏原型示範推定已可取得。

**提案：** 每核心記錄 canonical ID、取得事件、永久理解紀錄、取得後重訪變化、至少一個最終相遇回收。理解只讀永久紀錄；不把「拿到」當「已明白」。檢查 01→10、10→01 是否只是對照，或會成為互相等待而無入口的迴圈。

**驗收：** 每核心可先於解讀取得；解讀先於核心取得也能稍後生效；不持旅程信物仍保留理解；相遇不因少特定核心卡住普通路線。

## Q06：未來地圖 ID 的潛在不一致

**證據：** 收藏室 MAP_INDEX 使用 `area-04-windcut-broken-bridge`／`area-10-refraction-observatory`；database 的未知地名遮蔽使用 `area-04-wind-bridge`／`area-10-prism-observatory`。後者用 visited 判斷是否顯示地名，若未統一，正式造訪後仍可能顯示「？？？」。已上線 03 有明確舊 ID 別名，不把相容別名誤當錯誤。

**提案：** 04／10 正式上線前定 canonical map ID，共用 registry 匯出名稱、收藏編號、遮蔽對應；舊 ID 透過顯式遷移相容。不要在這次盤點中替使用者決定新地圖名稱。

## Q07：湖畔對已攜帶本圖信物採當次取得限定

**證據：** `area03.ts:146–152` 從 plan.carriedItems 排除 tide_gauge_plate／silvered_shard，改加入當次 finds 的 rare event ID；JSON 的兩個 carry 欄也使用 rare_gauge_plate／rare_mirror_shard。因此只帶前一次本圖取得信物、當次拿另一物，不能按「行囊有這件」觸發對應事件。當前四圖池不足時允許同旅程重訪，這個差異已有可出現的條件；本次是靜態條件確認，未做完整湖畔重訪實機重現。

**提案：** 若意思確為「帶著」，把條件全部用 canonical item key，對當次已到期 finds 另轉成 item key 後合併；保留每探索最多一件限制。若刻意限當次取得，就同步改設計文字，並說明對同旅程重訪的影響。

## Q08：主線時間因果與選玩缺頁的邊界

**證據與問題：** §48 主營火是霧中不會熄的火；缺頁二說第四天火熄，冷營地是營火映象。這可以成立為另一個可能未來，但目前文字未明確建立差別。§50 缺頁三說寫下路線會只剩一條；真結局最終選擇未定。05 告別提案也等待同一最終指令碼。這些是待編劇解答，不是確定的情節矛盾。

**提案：** 作者側先回答四題：主營火與冷營地的關係；何以借光只能短暫相遇；十核心為何能穩定領域；「留白」實際保留什麼選擇。主線對話提供必要答案，缺頁用具體經歷加深，不讓未玩隱藏圖的人看不懂結局。告別採能在任意取得順序下成立的片段；取得當下不直接揭露身份。

## Q09：同圖組合與段數的合法路徑

**證據：** 04 纜索扣與 08 覆寫墨水都是組合事件所在地的當圖信物。企畫要求一圖一次信物、同旅程盡量不重圖，隱藏圖也佔五段；幼苗已因這種限制改成跨旅程保留。若組合條件只讀入圖前行囊，04／08 組合可能缺一件；這兩圖未製作，尚非正式 bug。

**提案：** 對每組合用五個欄位寫一條合法路徑：「第幾段取得 A／第幾段取得 B／當次能否拾取後觸發／剩餘排程時間／錯過是否下趟可補」。同圖信物可在拾取後補入 eligibility；接近第五盞來不及演出時儲存待處理結果或允許重訪補知識，具體規則需定案。不要為解鎖支線新增第六段或提高稀有獎勵。

## Q10：重複母題要累加知識，而不是累加相似物件

**證據：** 02／03 都有同款燈芯、同種荷札編號；03 杯子／杯印與 07 手印／新舊刻度重複一舊一新；多地開場都用「從這裡開始」。這些是可用的連結，但回收沒做前容易讓玩家只得到「有人來過」的同一句暗示。

**提案：** 給每事件一個獨有新知識：02 證明照料仍持續；03 證明另一時間與現實不同；07 證明玩家能接下同一工作。編號鏈先定其辨識的物件；站牌磨掉後半要麼有後續永久回收，要麼明確當氣氛細節。發現卡片記具體事，收藏對照才做推論，避免取得時把謎底說完。

## Q11：檔案需要可辨識的歷史狀態

**證據：** CORE_PLAN_AGENT_BRIEF 開頭已記 03／07 整合，較下方的 2026-10-02 段仍寫 03 未整合、07 幼苗草案；§46／48 等早稿仍包含已被 §50／52／8 秒決策取代的描述。過去檔案有日期且可追溯，盤點不刪歷史。

**提案：** 在短記憶的舊段落加「歷史／由某日期取代」導航，產品規則與發布狀態分欄；新審查先找最晚修訂。手動文字與他人修改保留。這次只新增盤點入口，不批次重寫共用檔案。

## Q12：早領信物、重複物與結算措辭

**證據：** forestPlan 開始便選 journey_lamp（1–5），rollDueSpecialFinds 到該盞就儲存信物，不等全部完成；符合 §50.7 某盞出現，也保證完整時已經有。行囊以 Set 去重，同物再領的故事／持有數量語意未完整定案。§48.2 末句「燈不影響獎勵」容易與每盞核心抽選混淆。

**提案：** 明確使用「完整探索保證至少帶回一件；實際於安排燈到期領取」；普通重複物可保持持有布林但定義再次取得展示。規則檔案寫「燈不是品質等級；延長專注不增加五次抽選」，保留每盞結果儲存。釐清資料用詞，不自行新增貨幣／轉換獎勵。
