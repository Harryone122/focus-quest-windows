# 森林點燈與背景播放修正（2026-09-27）

## 問題

使用者回報專注 47 分鐘才看到旅人點第四盞，下方進度卻已是四盞；切到其他視窗後動畫停止，切回才追趕。

確認原因：

1. HUD 根據有效 Focus 時間，場景卻等走路與點燈動畫完成才更新燈。舊補追邏輯刻意留下最後一盞不亮，因此可能長期落後一盞。
2. 特殊發現不檢查下一盞燈的時間預算，會插隊。短停頓只檢查剩餘時間大於 60 秒，沒有預留走回燈旁的時間。
3. 每影格把 dt 截成最多 0.05 秒，同時用於走路與事件；低於 20 fps 時，這兩者落後真實有效時間。
4. 主視窗使用 Electron 預設背景節流。實測即使取消節流，Windows 最小化仍可能停止 RAF，故不能僅依靠 RAF 驅動世界。

## 修正契約

- `shared/lampTiming.ts` 的 `litLampCount` 同時供 HUD、地圖與後端抽選到期判定使用。
- 地圖根據收到的 `progressSeconds` 更新五盞燈，不使用插值時間提前亮、不等動畫結束才亮。50 分鐘路線的到期時間為 10／20／30／40／50 分鐘。
- 旅人在到期前準備點燈；環境事件、特殊發現與停頓都預留前往事件、演出、返回燈旁與準備的時間。獎勵已經保存，可以延後呈現，不會延後發獎或再抽一次。
- 重開剛好接近到期，或發生長時間畫面停頓時，燈直接恢復到已保存時間對應的狀態。旅人走到舊目標後不補演已過期的點燈；文字也不再說該燈「快到了」。
- 走路／事件使用實際影格間隔，視覺平滑仍保留 bounded dt；長時間缺幀依到期狀態恢復，不模擬大量積壓動畫。
- 主視窗 `backgroundThrottling: false`。場景保留 RAF，另用一個 33 ms watchdog 在 RAF 停止時呼叫**同一個** frame；沒有第二個計時來源或補播佇列。場景銷毀時清除此 timer。
- 手動暫停與系統睡眠依原本暫停狀態處理；背景播放不代表暫停後仍要推進。大廳維持原本保存的探索進度，只播放休息環境。

Claude 後续修改場景時請保留上述契約，尤其不要改回「只有 RAF 才更新」或「動畫完成才決定燈數」。既有角色、燈具與獎勵動畫的美術沒有重做。

## 驗證

- Typecheck、101 項測試與 production build 通過。
- `scripts/qa-lamp-sync.cjs`：以正式場景程式、可控測試時間跑三種 seed，各完整 50 分鐘，模擬每秒一影格並加入三種特殊發現。每秒核對實際燈亮度與 HUD 相同公式；第四盞於 40 分鐘已亮，三種 seed 旅人皆位於 `c_lamp`。也驗證暫停與長缺幀後第 4／5 盞恢復。
- `scripts/qa-focus-background.cjs`：真正 Electron 主視窗與隔離存檔，用其他視窗完全遮住、最小化、隱藏到系統列、恢復。直接記錄場景 WebGL 繪製而非只測 UI timer；背景持续繪製，切回無長時間停止／補播。手動暫停後最小化，專注時間與地圖截圖保持一致。
- 證據位於 `previews/lamp-sync-qa/`。所有改時間與獎勵的測試只使用獨立 QA 存檔，未修改玩家正式進度。
