# Codex × Claude 工作與交接方式

這份文件是兩個 agent 的共同工作規則。產品需求以核心企畫案 Markdown 為準；本文件只決定誰處理、如何驗收與交接，不改變遊戲規格。

## 共同交接入口（2026-10-02）

開工時讀 [COLLABORATION_STATUS.md](COLLABORATION_STATUS.md)，再讀本次工作對應的最新交接。完成後更新原交接文件及索引中的對應列，讓下一位自行從檔案接續，不要求使用者搬運完整 prompt。索引不取代企畫與正式程式，也不新增實作授權。設計預覽、原型試用及使用者驗收關卡保留。

目前這是共用檔案工作流，沒有自動喚醒兩個 App。共用索引不是檔案鎖；正在執行的對話不會自動讀到規則更新。仍須遵守下方的寫入分工與檢查，尚未確認共用檔案的 active writer 時先唯讀。

## 分工（2026-09-27 使用者更新，取代舊版前端實作分工）

使用者決定：**Claude 只負責設計，其餘工作由 Codex 完成。**

| 領域 | 主要負責 | 交接界面 |
| --- | --- | --- |
| 地圖概念、構圖、鏡頭、角色與美術方向、UI 版型、動效及互動設計 | Claude | 設計說明、參考圖、素材或網頁原型；附已有的座標、路線、燈位與事件描述 |
| 正式 App 的前端與場景程式、動畫播放、網頁原型移植、後端規則、計時、存檔、共用介面與錯誤修正 | Codex | 依已驗收設計完成實作；不必等待 Claude 提供正式場景模組 |
| 整合、測試、開啟 App、截圖／錄影、實機驗收及 Windows 打包 | Codex | 完成技術驗證與測試版；使用者驗收最終體驗 |

網頁原型是有效的設計交付，不代表 App 已完成整合；移植與接線由 Codex 接手。Codex 可以直接修改前端、場景及動畫程式，保留已驗收的外觀與演出，不把程式修正退回 Claude。需要設計取捨時才釐清設計，不因缺少正式 App 模組就停工。

地圖與五盞燈的視覺錨點來自設計；有效 Focus 時間、結果與保存仍由本機後端決定。這次分工更新不改變遊戲規則，也不授權自行重設已驗收畫面。

## 事件與動畫交接

- Claude 設計事件內容、角色動作、場景／UI 動效與預期呈現；Codex 實作播放程式，以及事件抽選、觸發條件、時機、結果與持久化。
- 有原型或素材即可交付。事件／動畫清單盡量帶名稱或識別、觸發時機、所需狀態、是否純視覺與結果回報；缺少的工程契約由 Codex 依設計補齊。
- 改變路線、Tag、信物、獎勵或永久進度的新事件須符合企畫書並經使用者確認，已授權的規則無須重複確認。Focus 期間不要求玩家操作；選擇留到結束後。暫停、重開或動畫失敗時，以已保存結果為準。

## 現階段：同一個工作目錄，輪流寫入

**2026-10-11 Git 基準更新：**使用者已授權保存全部目前進度並推送；已建立私人遠端 `https://github.com/Harryone122/focus-quest-windows`，本次基準分支為 `checkpoint/progress-2026-10-11`。下文 2026-09-25 的「未提交／沒有遠端」及文末「目前沒有 Git remote」為歷史狀態，由本段取代。接續方式、驗證與本機保留檔案見 `GIT_CHECKPOINT_2026-10-11.md`。共用工作目錄仍須輪流寫入；推送本身不會同步另一工作目錄，也不會喚醒另一個 agent。

截至 2026-09-25，`main` 與現有五盞燈 worktree 都有大量未提交修改，重要的企畫文件、場景程式及美術素材尚未進入 Git 版本；此 repo 也沒有設定遠端。開始新任務前仍須重新檢查現況。現在從舊 HEAD 開新 worktree，可能看不到當前地圖；不要把這種缺檔誤判成素材被刪除。

1. 一次只讓一位 agent 修改同一個工作目錄。另一位可唯讀檢查；若任務急需並行，先確定完全不同的檔案範圍與執行環境。
2. 開工前檢查 Git 狀態，列出本次要改的檔案。`App.tsx`、`ExplorationScene.ts` 等共用檔案由當次任務指定一位寫入者。
3. 不執行會丟失他人修改的 `reset`、`clean`、`stash`、覆寫或整目錄同步。發現非自己造成的變更時，保留並在交接中說明。
4. Claude 設計完成後交付設計摘要、檔案清單、可用原型／素材、預期行為及未決設計問題；已有的檢查可一併提供，不要求生產模組或 App 驗證。Codex 接手完成前後端實作、檢查、開啟 App、截圖／錄影、實機驗收與打包。不要求 Claude 為交接設定 nvm／模擬環境。接手者先讀交接，再開始寫入。

## 基準版本完成後：各自工作目錄

先由使用者與 Codex 整理並驗收目前改動，建立包含必要企畫文件、程式、素材的 Git 基準提交；不要把測試資料庫、暫存影片或大量無關預覽一併加入。之後 Codex 與 Claude 從同一基準提交建立各自的 branch/worktree，平行工作；每位 agent 只在自己的工作目錄提交，另一方以 commit/branch 的差異接手，由 Codex 整合、跑完整測試並檢查實際 App 畫面，Claude 可依回饋調整設計，由 Codex 實作修正。Git worktree 只包含已提交的內容；未提交與未追蹤檔案不會自動同步。

## 是否需要推上 Git？

同一台電腦交接只需要本機 Git 提交與合併，不需要 `push`。推送用於遠端備份、不同電腦協作或 Pull Request；先設定遠端，再推個別功能分支。不要把直接推 `main` 當成交接方式。目前沒有 Git remote，因此此時不能直接推送。任何交接都應附上可驗收的結果，而不只是一個 commit。
