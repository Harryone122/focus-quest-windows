# 雲上遺庭（01）：開場、首訪／第二次造訪、雲鯨與線索

Claude 設計，2026-09-29。依企畫書 §48–§50 補齊這張地圖的故事事件。使用者已確認方向（見第 1 節）。**本文件是設計規格，正式實作由 Codex 負責。**

- 可操作的原型：`docs/prototypes/cloud-ruins.html`。可切換情境（開場、首訪、首訪第五盞燈後、第二次、第三次以後）、勾選攜帶的信物，並直接播放每個事件。
- 原型用的完整場景原始碼：`docs/prototypes/src/cloudRuinsStory.js`。它以 2026-09-29 當時 App 的 `cloudRuinsScene.js` 為基礎，只多了「story events」一段與少量掛勾，可以直接和 App 版比對差異後移植。
- 既有事件、錨點與動作請看 `AREA_01_CLOUD_RUINS_EVENTS.md`。本文件只寫新增與修改的部分。

## 2. 第一次專注的開場（§49.6）

| 項目 | 規格 |
| --- | --- |
| 條件 | 整個遊戲的第一次探索，而且第一段選了雲上遺庭 |
| 開始 | 有效時間 40 秒後，旅人下一次空檔時開始（不插隊打斷點燈與已保存的發現演出） |
| 長度 | 橋頭約 26 秒＋走過石橋約 30–40 秒＋樹下 14 秒，一定在第一盞燈（10 分鐘）之前結束 |
| 畫面 | 見下表 |
| 介面 | 開始時 `reportCinematic(true)`：Focus 的標題列、暫停／結束按鈕、狀態列和它們的玻璃一起淡出（約 0.6 秒）；樹下那段結束時 `reportCinematic(false)` 淡回。播放中也不能拖曳鏡頭 |
| 紀錄 | 樹下那段結束時回報 `c01_first_tree`。回顧畫面一定顯示這一條 |
| 中途結束專注 | 還沒播或沒播完就結束：回顧照樣給 `c01_first_tree`；下次繼續同一次探索時不補播 |
| 暫停 | 照常凍結；恢復後接著播，介面維持隱藏直到播完 |

| 階段 | 錨點 | 旅人 | 畫面 | 狀態列 |
| --- | --- | --- | --- | --- |
| 1 | 石拱橋頭 `a_bridge`，面向大樹 | 拿出筆記、低頭看第一頁 | — | 旅人在橋頭停下來，翻開筆記的第一頁 |
| 2 | 同上 | 把筆記舉高，對著遠處的大樹 | 空中出現筆記上的墨線素描，從樹根往上「畫」出來，剛好疊在真的大樹上 | 旅人把筆記舉起來，對著遠處那棵大樹比了比 |
| 3 | 同上 | 維持 | 素描旁寫出手寫的「從這裡開始。」 | 筆記第一頁的大樹，和眼前這一棵一模一樣 |
| 4 | 走過石橋 | 闔上筆記，走向大樹 | 素描淡掉 | 旅人闔上筆記，走過石橋，往那棵大樹走去 |
| 5 | 中央大樹 `b_tree` | 手貼在樹幹上，抬頭看樹冠 | 幾片葉子落下 | 旅人把手貼在樹幹上，幾片葉子落了下來 |

- **素描的畫法**：以固定鏡頭（方位 45°、仰角 31°）投影大樹的樹冠球體與樹幹，只留樹冠外輪廓，加幾筆葉子與地面線。用墨色筆觸，外面墊一層淡紙色，讓線條在深綠樹冠上也看得清楚。畫在一張面向鏡頭、`depthTest: false` 的 Sprite 上。原型中的函式是 `buildSketch()`／`drawSketch()`。
- 如果第一段選的不是雲上遺庭，之後第一次來這裡時改播**首訪版**（第 3 節），紀錄相同，只是不隱藏介面，時間也不固定。

狀態列文字依序是：
- **井底的燈**：「探頭往古井裡看，愣住了」→「井底的水面上有一串燈的倒影，井邊卻一盞燈也沒有」→「旅人起身，望向瀑布落下去的那一頭」
- **碑緣刻度**：「蹲在索引石碑前，手指順著碑緣摸下來」→「碑的邊緣有一排很細的刻度，旅人順著摸了下來」
- **樹旁痕跡**：「在樹旁停下來，看著一塊被壓平的草地」→「旅人發現旁邊的行囊，綁法跟自己的一模一樣」→「樹皮上刻著一個日期。旅人摸了摸，拿出筆記寫了幾行」

補充說明：
- 抽選規則比照一般事件：必須在下一盞燈前做完（`fitsBeforeLamp`），而且排在已保存的特殊發現之後；開場是唯一的例外。
- 井的方位指向**瀑布下游**。這和苔痕驛站 `h1b`「霧瀑下游常有熄掉的燈漂過去」是同一個方向，兩條方位線在線索桌上交會，就是沉燈灣。
- 碑緣刻度與樹皮日期的模型已經放在場景裡，平常幾乎看不出來。刻度是 15 條細槽，每 5 條一條長的；日期目前用佔位的「11·02」，**實際日期要和 07 封存種莢的採集日期一起定**。

## 5. 專屬環境變化：雲鯨過境

規則比照苔痕驛站的天氣（`src/shared/weather.ts`）：用純函式依有效時間與 seed 計算，不需要另外存；手動暫停時凍結；**不影響燈、信物、核心與保底，也不產生線索**。

| 參數 | 值 | 說明 |
| --- | --- | --- |
| `every` | 240 秒 | 第 k 次擲骰在 k × 240 秒 |
| `chance` | 0.06 | 一次 50 分鐘的探索約一半會遇到一次 |
| `dur` | 80 秒 | 一次過境，含前後各約 8 秒淡入淡出 |
| `cooldown` | 720 秒 | 上一次過境後 12 分鐘內不再擲骰 |
| 開始時間 | k × 240 + 0～40 秒 | 同一個 seed 永遠得到同樣結果 |
| seed | 建議與天氣相同：每段 Focus 一個（例如 `weatherSeedFrom(sessionId)`） | |

- **畫面**：
  - 一頭由雲團組成、半透明的大鯨，從畫面左邊慢慢游到右邊，高度在浮島上方（約 y = 11.5）。
  - 身體是 8 節漸細的橢球，背上有雲團；兩片胸鰭，尾鰭上下擺。
  - 顏色跟著當下的光線（晨、日、暮、夜都自然）。
  - 牠的影子沿著太陽方向落在島上，是一個柔和的橢圓，夜晚幾乎沒有；經過頭頂時陽光暗一點（最多 14%）。
- **旅人**：
  - 經過時，只要旅人不在有紀錄的事件中，就抬頭看。
  - 下一次空檔時插入一次 18 秒的「停下腳步，抬頭看一頭雲做的鯨慢慢游過」。這一步和其他事件一樣，必須趕得上下一盞燈。
  - 狀態列出現一次「一頭雲做的鯨，從浮島上方慢慢游過」。
- **可抽選的事件**：過境期間可以加入「跑到島緣目送」（`a_edge`、`e_edge`、`b_falls`）。原型只做了原地抬頭。
- 風哨事件（第 4 節）會在當下安排一次過境，不受擲骰與冷卻限制。
- 伏筆：06 的核心是**蒼鯨號角**，但遊戲裡不直接說出關係。

### 這些線索怎麼拼出故事（作者側，遊戲中不直接說出）

1. `c01_first_tree`：旅行筆記是從這棵樹開始的。
2. `c01_bark_date` ＋ 07 種莢：樹上的日期比樹還老，而且和種莢的採集日期相同。這棵樹是有人帶著未來的種子種下的。
3. `c01_tag`：種樹的人留下照料者的叮嚀，和玻璃苗圃是同一個人的口吻。
4. `c01_rubbing` ＋ 02 羅盤：「燈點完再走」是同一個人的習慣，他在碑上也刻過，後來被磨掉了。
5. `h1a` ＋ 沉燈灣缺頁一：井底倒映著另一次的燈，那是他迷路那一晚被點亮的燈。
6. `c01_stele_scale` ＋ 10 目鏡：從這裡就在觀測同一個方向，也就是最終領域。

## 8. 場景介面（原型實作，供移植參考）

`createCloudRuinsScene(host, options)` 新增：

| 名稱 | 說明 |
| --- | --- |
| `options.story` | `{ visit, opening, items, whaleSeed }`。`visit` 是這次的造訪次數；`opening` 表示這是整個遊戲的第一次探索；`items` 是這一趟攜帶的信物 key（原型用 `charcoal_paper`、`pressed_leaf`、`wind_whistle`） |
| `options.reportStoryRecord(id)` | 有紀錄的事件播完時呼叫（第 6 節的 id）。只是畫面訊號，**後端以自己保存的結果為準**；開場的紀錄即使沒播也要給 |
| `options.reportCinematic(on)` | 開場開始與結束。App 依此淡出／淡回 Focus 介面，並把場景玻璃 `setUiFade(0 / 1)` |
| `handle.playStory(key)` | 原型與 QA 用：立即播放（`opening_a`、`notebook_a`、`stele`、`well`、`rubbing`、`leafTag`、`whistle`、`traces`、`whale`） |
| `handle.__advance(sec)` | 原型與 QA 用：以 50 毫秒固定步長推進有效時間 |

原型裡各事件的開始時間（`storySched`）只是示範。正式規則是：由後端判斷造訪次數與攜帶的信物，在第 3、4 節的時間窗內安排，並和一般事件一樣必須趕得上下一盞燈。
