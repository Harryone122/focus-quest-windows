## 1. 使用者的決定（2026-09-27）

1. **地圖方向**：企畫書 §46.6-02 的「樹根包圍的山間驛站」，採用概念 C（森林棧道車站），並參考群馬縣上神梅駅：木造站房、低月台、單線鐵軌、腕木號誌、花圃與郵筒。
2. **像空島一樣有天空與留白**：驛站建在一塊懸崖台地上，外側是霧海。霧下面要**若隱若現看得到山巒**（被淹沒的山谷、杉林與遠方稜線）。
3. **可互動的地點要多**：新增長滿青苔的大石頭（苔石）、舊道標、石地藏、倒木、湧泉、手水鉢、柴堆、廢棄貨車等。
4. **屋頂青苔要真實**，屋簷垂下蕨類（含吊りしのぶ與風鈴）。
5. **天氣系統**：新增下雨。支線上的廢棄貨車是躲雨地點。
   - 每 3 分鐘有效專注時間擲一次，**15%** 機率下雨，一次下 **5 分鐘**。
   - 雨停後 **15 分鐘內不會再下雨**。
   - **天氣和日夜是兩條線**：早中晚照樣 10 分鐘一循環，不會被下雨延誤；但**只要下雨就一定是陰天**。
6. **特殊發現**：
   - 旅程信物一：**舊荷札**（舊木製行李牌，刻著車站名稱與編號），取代企畫書原本的「結繩路記」。
   - 旅程信物二：**炭印紙**，並做一個**雨天版本**（下雨時改從住宿簿裡取得別人已經拓好的一張）。
   - 地圖核心：**裂痕羅盤**，放在售票窗口下的**遺失物抽屜**。
7. 燈、信物、核心、保底的規則和雲上遺庭相同。**天氣不影響任何獎勵與燈的時間**，只影響畫面、旅人行為與可抽選的事件。
8. 驗收後的修改（2026-09-27 下午）：
   - 走苔痕隧道離開時，旅人要**走進洞口**，不能爬上山。
   - **不從鐵道棧橋離開**。改成在小河最右邊（東端）搭小舟：溪水在那裡匯成小潭、從崖邊落成瀑布，旅人坐上繫在棧橋旁的小舟，順著瀑布滑進霧海。鐵道棧橋保留為一般事件地點。
   - 白天已點亮的月台燈要看得見：燈泡移到燈罩下方並加大，白天加一層暖色光暈。
   - 早中晚的切換要有**隨時間慢慢變化**的漸變（第 17 節）。
   - 瀑布與溪水要像真的水，不能只有幾條白線；兩道瀑布都要有水花（第 18 節）。

## 3. 座標與鏡頭

- 與雲上遺庭相同：`u` 往畫面右，`v` 往畫面深處，`y` 往上。世界座標 `x = (u − v)/√2`、`z = −(u + v)/√2`。
- 正交鏡頭（方位 45°、俯角 31°），可拖曳偷看、放開回彈。
- 旅人身高約 0.95（前端放大 1.15 倍顯示）。正式 App 步行速度建議 **0.35 單位／秒**。
- JSON 內節點的 `y` 是前端走面高度（地形、棧道、月台、倒木、踏石）算出的值；路段的 `via` 第三個數字也是。
- 台地邊緣以外是霧海與山谷，旅人不可進入；溪流只能走踏石或倒木過去。

## 4. 路網

地圖分成五區：西側入口棧道（`w_*`）、鐵軌與號誌（`t_*`、`x_cross`）、月台與站房（`p_*`）、站房後的住宿小徑（`l_*`）、南側森林與崖邊（`f_*`、`r_*`），以及支線（`s_*`）。

入口是 `entry0`（霧裡的木棧道外端）。**出生與等待點是 `w_gate`**（沿用 0.6.10 的做法：`entry0` 只當路線外端，不當停留點）。出口是 `exit_boat`（小河東端的棧橋與小舟）與 `exit_tunnel`（東側苔痕隧道）。西側鐵道棧橋 `t_trestle` 不再是出口，只當事件地點。

溪流東端是一個小潭，溪水從這裡分兩頭流：往西經過踏石、倒木流到西側瀑布；往東越過崖邊，形成東側瀑布（離開用）。湧泉 `s_spring` 移到小潭北岸的岩石旁，有一根竹筧把泉水引進潭裡。

## 7. 天氣

### 7.1 排程（`src/shared/weather.ts`）

| 參數 | 值 | 說明 |
| --- | --- | --- |
| 時鐘 | 有效專注秒數 | 與日夜相同；手動暫停時凍結 |
| `rollEverySeconds` | 180 | 第 k 次擲骰在 k × 180 秒 |
| `rainChance` | 0.15 | |
| `rainSeconds` | 300 | 一場雨 5 分鐘（含前後各約 30 秒漸變） |
| `cooldownSeconds` | 900 | 雨停後 15 分鐘內的擲骰直接跳過 |
| `afterRainSeconds` | 240 | 雨停後 4 分鐘地面慢慢變乾，`phase = 'afterRain'` |

- `weatherAt(seed, seconds)` 是純函式，回傳 `{ phase, overcast, rain, wet, window }`。同一個 seed 與秒數永遠得到相同結果，所以 HUD、場景、重開 App、QA 不需要另外存天氣。
- **seed**：建議每段 Focus 一個，用 `weatherSeedFrom(sessionId)` 從 session id 產生。這樣每次專注的天氣不同，但重開同一段 Focus 時一樣。若 Codex 想用 Daily Expedition 種子，也可以，只要後端與場景用同一個值。
- **頻率提醒**（2 萬個隨機 seed 模擬）：50 分鐘的 Focus 約 **93%** 至少下一場雨，平均 1.4 場；25 分鐘約 73%。這是依使用者給的參數算出的結果，如果使用者覺得太常下，只需調 `rainChance` 或 `cooldownSeconds`。
- 天氣與日夜分開：場景用 `timeOfDayAt` 決定早中晚，再用 `overcast` 把晴天與雨天兩組光線混合。下雨時一定是陰天；雨停後約 12 秒雲散開。
- **天氣不影響獎勵**：燈的時間、信物、核心的 5% 抽選與保底都不看天氣。

### 7.2 事件的 `weather` 欄位

| 值 | 可抽選的時機 |
| --- | --- |
| （無） | 任何天氣；但下雨時只有躲雨事件會被選（見 7.3） |
| `dry`、`notRain` | 沒在下雨（包括雨停後 240 秒內） |
| `rain` | 雨中 |
| `afterRain` | 雨停後 240 秒內（葉子還在滴水、地面還濕） |

`weatherAllows(condition, phase)` 已經實作這張表。

### 7.3 下雨時的旅人行為（建議規則，Codex 可調整）

1. **雨開始時**：
   - 正在做的事件若是純演出（`outcome: ambient`），提前結束；有結果的事件（筆記、發現）照常做完。
   - 正在走向一般事件的，取消。
   - 特殊發現、點燈、走向燈，**都不中斷**。
   - 休息中的活動若標 `weather: dry`，換成雨天的休息活動。
2. **下雨期間的抽選**：只選 `shelter: true` 的事件（遮蔽處：`p_bench`、`p_door`、`s_wagon`、`l_arch`、`l_hut`）。旅人如果已經借了傘，另外可以選 `weather: rain` 的戶外事件（例如去看漲水的溪）。
3. **借傘**：下雨時，如果下一盞燈會在這場雨結束前到期，而且本次遠征還沒借過傘，旅人先到候車室門口 `ev_umbrella_borrow` 借傘，再撐傘去點燈。借到傘後，走路、等燈、點燈都用撐傘姿勢。
4. **還傘**：雨停後若旅人手上有傘，最優先插入 `ev_umbrella_return`：把傘掛回傘架，留一條擦乾的手巾（世界記憶 `towelLeft`）。
5. **雨停時**：躲雨事件與雨天休息提前結束，正在走向躲雨地點的取消。
6. **路線**：下雨時不走 `f_stones_n` ↔ `f_stones_s` 的踏石。
7. 抵達事件地點時要再檢查一次天氣；條件已不成立就放棄這個事件（特殊發現除外）。

## 17. 早中晚的漸變

- **正式 App 本來就是連續漸變**。`timeOfDayAt` 把 10 分鐘分成晨霧、白天、薄暮、夜四段，每段 150 秒。每段內從這一段的光線用 smootherstep 慢慢混到下一段，所以隨時都在緩慢變化，沒有跳格。雲上遺庭的 `cloudRuinsScene.js` 每一幀都用 `timeOfDayAt(sim)` 算目標光線，苔痕驛站移植時會沿用同一套。暫停時有效時間不走，光線也跟著停住。
- **原型頁會跳的原因**：「晨霧／白天／薄暮／夜」四個按鈕是直接跳到某個時段的預覽，原本沒有過場，所以看起來是瞬間切換。現在這四個按鈕和「直接看完成後」都會用約 2.8 秒淡過去。選「依時間」就是正式 App 的行為。
- 天氣的陰天也是連續的：`weatherAt` 的 `overcast` 在雨前約 30 秒內慢慢變陰，雨停後約 12 秒雲散開，再和日夜的光線混合。
- 移植時，場景只要每一幀把 `timeOfDayAt(有效秒數)` 與 `weatherAt(seed, 有效秒數)` 的結果混合，就會自動得到這兩種漸變。後端不需要送額外的過場狀態。

## 18. 水：溪面水流、瀑布與水花（純視覺，2026-09-27）

使用者覺得原本的瀑布只有幾條白線、太假，兩道瀑布和溪水都改用 shader 畫。這些都只是前端畫面，不需要後端參與。時間用場景的動畫時鐘，手動暫停時水也停住，和世界其他部分一致。

- **溪面水流**：溪面上多蓋一層半透明的水紋，由小潭往東、西兩頭流。
  - 水面上有順著水流拉長的細白紋，兩岸邊有細泡沫線。
  - 越接近崖邊水越急，出現白色急流；小潭本身幾乎不動。
  - 下雨時泡沫變多。
  - 溪面在離崖邊最後半個單位往下彎，接上瀑布，不會出現截斷的硬邊。
- **瀑布本體**：每道瀑布是兩層半透明水幕，形狀照真實的拋物線：水越過崖邊時先往前衝，再往下落。
  - 崖邊那一段是透明、帶一道亮光的「玻璃水」，往下逐漸充氣變白。
  - 水紋往下捲動得越來越快，因為水在加速。
  - 水幕下半段會撕成一束一束，最後散進霧裡。
  - 邊緣是不規則的，水幕本身會輕微擺動。
  - 顏色跟著日夜：夜裡暗、白天亮，也會受霧影響。
- **水花**：每道瀑布約 220 個粒子，分三種。
  - 沿著水幕落下的水珠與泡沫團。
  - 在崖邊石頭上濺起的小水花。
  - 瀑布腳下往上翻的水霧。
- 小舟離開路線（`offMap`）已改成沿東側瀑布的同一條拋物線滑下。
- 移植時照原型的 `brookFlow()`、`waterfall()`（`docs/prototypes/moss-station.html`）搬進場景模組即可。每一幀需要餵：`uTime`（動畫時鐘）、泡沫與深水顏色（由目前的霧色與天空亮度算出）、`uRain`（`weatherAt` 的 `rain`），粒子另外需要每單位的像素數。

### 19.3 排程規則（給 Codex）

- **開場**：出生後 0:15 開始、0:55 前結束，在第一盞燈之前。天氣第一次擲骰在 180 秒，所以一定是晴天，不用雨天版。線索 `m02_open` 由第一次專注的回顧發放，不等動畫播完；未滿 5 分鐘門檻、暫停、重開或動畫中斷都照發（§49.6「回顧一定有一條新紀錄」）。播放期間比照雲上遺庭的開場：隱藏所有 Focus 功能鍵與玻璃（`reportCinematic(true)`），演出結束再淡回，不能拖鏡頭。
- **首訪／第二次**：探索開始時就像特殊發現一樣排進某兩盞燈之間（建議第 1–4 盞之間），不和同一次探索的信物、核心排在同一段，並預留走回燈的時間。雨天版本在旅人**出發去做的那一刻**依天氣決定（同炭印紙），出發後不改；下雨不取消已出發的故事事件。
- **核心事件**：每件只發生一次（拿到線索後不再排）。
- **信物事件**：每次探索最多一件，照一般事件偽隨機、就近優先；苔痕自己的信物要在同一次探索取得之後才算「帶著」。第一次發生時寫一條永久線索（`clueOnce`），之後再發生只有畫面與這一趟的新發現卡。線索是查到的紀錄，「看懂了一些」不讀此刻有沒有帶信物；信物每趟隨機，所以這類線索**不能是隱藏地圖解鎖的唯一來源**（沉燈灣的 `h1a`、`h1b`、`h1c` 都不需要信物）。
- 線索的 `mentions` 是文字裡提到的地圖；還沒去過時顯示「？？？」。

## 20. 旅人不能穿過場景物件（2026-09-29，使用者要求）

使用者指出遊戲中旅人常常穿模。Claude 在原型裡逐格檢查整張路網：沿每條邊每 0.1 單位，檢查旅人的身體（半徑 0.27，腳到 0.8）與帽簷（半徑 0.36，高度 1.05–1.2）會不會碰到場景物件（草、蕨、水面、地形不算）。修正後，除了入口棧道最底端（霧裡、旅人還在淡入）與棧橋兩側木樁（差 3 公分）之外，全部路線、所有站位與事件的站位都不再碰到物件。
