# Focus Quest 精簡交接

本檔為兩邊共用規則；路徑皆相對 repository 根目錄。產品權威與初次開工必讀文件沿用 AGENTS.md，不以摘要替代企畫。

## 先判斷負責人

- Claude：美術、構圖、角色、UI 版型、運鏡、動效／互動設計、故事呈現，以及表達設計的 HTML 原型／素材。使用者偏好 Claude 美術；Codex 保留已驗收設計。
- Codex：正式 App 前後端、原型移植、動畫播放接線、計時／五燈／路線／獎勵／存檔、修錯、測試、實機 QA、整合與打包。
- 判斷依「要改的交付物」，不是關鍵字：修改 HTML 原型的動效屬 Claude；修正式 App 的同一動效屬 Codex。混合請求先做自己範圍，交接其餘部分。
- Claude 收到 Codex 範圍的請求時，不開始工程修改；簡短說明分工，指出交接路徑並給一行可轉交的請求。例如：「這是正式 App 的存檔修正，依分工由 Codex 處理。請轉到 Codex：『請讀 docs/area07/CODEX_HANDOFF.md，修正……』。」已有檔案就自己讀，不要求使用者搬運內容。不能假裝已通知另一個 agent。
- Codex 收到新的美術方向需求時，引導 Claude 設計；已驗收設計的移植與技術修正自己完成。使用者明確變更分工時，以新指示為準；不把一般工程請求自動當成變更分工。

## 最少必要讀取

1. 首次開工依 AGENTS.md / CLAUDE.md 讀必讀文件一次；本輪已讀過就沿用。不要每個操作重讀。
2. 執行 `powershell -NoProfile -ExecutionPolicy Bypass -File .agents/skills/focus-quest-handoff/scripts/read-index.ps1 -Topic 'Area 07'`。Bypass 只作用於本次讀取程序，不改系統設定。Topic 用使用者指定的地圖／工作名稱；不知道名稱時不傳 Topic，取得所有短列。比對不命中時改用地圖名稱／編號，或搜尋索引，不把無命中當成沒工作。
3. 只讀匹配列所連結、與本次問題最相關的 1–2 份交接。先找「目前交接摘要」；沒有摘要時先列標題與日期，再讀最新相關段落及其引用的必要規格。來源摘要有省略，不能當成完整需求或批准證據。
4. 實作前再按需讀相關正式程式、測試與企畫章節。若日期、批准範圍、狀態互相矛盾，查原始依據；不能只相信索引、最高版本號或最後一段。未決設計不因交接而獲授權。

## 交付時維護一個短摘要

在既有交接文件頂部（標題後）更新「目前交接摘要」，不另複製一份規格：日期、狀態、下一位＋一個動作、已批准範圍／批准來源、涉及檔案、未決項／驗證證據。控制在約 12 行；詳細回報保留原處，摘要連到對應章節。

索引相應列只留短狀態、下一位與一個動作、詳細來源；不要把整份驗證報告搬進表格。只更新本次項目，不刪除他人歷史。寫入前確認 active writer；索引不是鎖，Git worktree 不會同步未提交檔案。

設計完成、正式整合完成、測試版交付、使用者驗收分開記錄。交接不是自動喚醒，也不要求使用者轉貼長 prompt。
